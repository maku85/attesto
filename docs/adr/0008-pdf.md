# 0008: The installed browser prints the PDF

Status: accepted. Brings forward a feature planned for 1.1.

## Context

A CV is sent as a PDF. The HTML output is already built from the lines the provenance report covers.

## Decision

- A PDF is the HTML, printed by an installed Chrome, Chromium or Edge in headless mode. No dependency is
  added, and there is no second layout to keep in step with the first.
- The browser is looked for before anything is paid for. The PDF is written last, so a browser that fails
  costs nothing else.
- The page has no scripts, and a content security policy blocks every request. The browser runs with a
  temporary profile in a directory only the owner can read.
- Templates are style sheets over one HTML structure in reading order, so that software that extracts
  text reads the same from each.
- `attesto render` restyles a past run without an LLM. It uses the document and the decisions in the
  database, never a file, and stops if an entry behind a claim has changed. It cannot be used to render a
  claim that was not accepted.

## Consequences

- Fonts are the system's, so the same CV can break pages differently on another computer.
- PDFs contain a time stamp, so their hashes differ between runs.
- A claim edited by hand cannot be rendered. Change the knowledge base and generate again.
